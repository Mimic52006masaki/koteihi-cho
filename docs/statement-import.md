# 銀行明細の取り込みと要確認一覧

## 導入

既存DBのバックアップとスキーマ確認後、`sql/migrate_v4_imports.sql` を一度だけ適用する。既存テーブルの変更・削除はなく、原明細と変更履歴の2テーブルを追加する。PHP 8.1以上（PDO MySQL）が必要。新規環境は既存のv3までのスキーマを先に構築する。

`app/services`、`bin`、`public/api/imports`とフロントエンドのビルドを配備する。現在の本番DBへの適用・定時タスクの切替は別途確認して実施する。適用前に新しいAPIを利用するとエラーになるためDB移行を先に行う。

## 操作（サーバー内CLI専用）

認証済みSSH環境から実行する。DB_HOST/DB_NAME/DB_USER/DB_PASSは保護された環境設定から読み込ませ、引数や履歴に秘密情報を書かない。既存のMySQLクライアント設定はPDOに自動継承されないため、環境設定を配備時に確認する。

```sh
php bin/import-payments.php --user=1 --file=/secure/statements.json
php bin/import-payments.php --user=1 --file=/secure/statements.json --commit=プレビューに出たpreview_hash
```

初回は読取専用プレビュー（トランザクションをROLLBACK）。commit時はDBを再照合し、入力または判定対象のDB状態が変わっていれば全件反映せず再プレビューを要求する。想定される曖昧さは項目単位で保留し、確実な他項目は反映する。DB障害など予期しない失敗はバッチ全体をROLLBACKする。

入力はJSON配列。金額は出金額の正整数、日付は銀行に表示された日付。

```json
[{
  "source_key": "mf:bank1:2026-09-20:stable-statement-id",
  "account_id": 1,
  "amount": 8580,
  "paid_date": "2026-09-20",
  "description": "銀行に表示された原文",
  "monthly_fixed_cost_id": 123,
  "match_evidence": "固定費名と銀行明細名の既知の対応、引落口座を確認"
}]
```

- source_keyはユーザー内で永続・一意。同じ明細の再実行や再照合でも変更しない。銀行の安定IDが取れなければ、口座・日付・原文・金額・同一組み合わせの出現番号からSHA-256等で作り、以前の識別と整合させる。ランダムIDを毎回作らない。レシートと銀行明細を二重に投入しない。
- 名称の自動推測は行わない。呼出側が既存の照合ルールで名称・口座・対象月次の対応を確認し、根拠を明記する。match_evidenceは照合済みであることの宣言であり、サービスが銀行原本の真偽を検証するものではない。
- 対象が不明ならmonthly_fixed_cost_idをnull、match_evidenceを空文字で投入すると要確認一覧に残る。マスタは自動作成しない。
- 既存支払いが一件、同口座・同額・日付差3日以内で一意なら紐付け／日付補正。同対象に複数の銀行明細がある場合は同じバッチに含める。複数候補・金額や口座の不一致・入金・振替・closed月次は保留。
- 既定口座変更・複数明細の合算・差額解消を推測で行わない。明細を分割バッチにして曖昧さを回避しない。
- 取込ではaccounts.balanceとaccount_historiesを変更しない。従来の残高照合・同期は独立して継続する。
- 原明細は不変。保留解決は同じsource_keyと原文を維持し、対象ID・照合根拠を更新して再プレビュー／commitする。既存支払いが誤っている場合は正規の修正手順で確認・訂正した後に再照合する。
- Webの「明細の要確認」は認証済みユーザーの原明細・照合時の登録値・保留理由を表示する。登録値は照合時点のスナップショット。ブラウザから支払いを強制確定する機能は設けていない。
- CLIの出力には取引情報を含むため、共有ログへ貼らない。履歴はimport_eventsへ保存する。

## 検証

`tests/Dockerfile`でPHP/PDO環境を構築し、**使い捨ての空MySQL DBのみ**で`php tests/imports.php`を実行する（テスト用テーブル・架空データを作成する）。本番DBでは実行しない。フロントエンドは`npm test`と`npm run build`。

## 戻す場合

旧アプリへ戻して取込ジョブを停止する。追加2テーブルと履歴は削除しない。取込済み支払いは残るので、履歴確認なしに旧SQLによる再INSERTをしない。

Dockerが使える場合は`sh tests/run-imports.sh`で空の専用DBを作って検証できる。テスト終了時に専用コンテナとネットワークを破棄する。本番の接続情報は使用しない。
